3. Comprehensive System Architecture

The architecture decouples the static presentation tier from the dynamic serverless lead processing engine:

A. Edge CDN & Web Delivery
  • CloudFront Edge PoPs: Dedicated edge locations in Dubai and Fujairah cache static HTML, JS, CSS, and 3D assets for sub-20ms latency.
  • Next.js 14 Static Export: Pre-rendered static pages eliminate server boot time and CPU compute costs entirely.
  • Brotli & Gzip Compression: Automatically compressed at the edge to reduce data transfer payloads by up to 70%.
B. Serverless Lead Processing
  • Lambda Function URL: Bypasses traditional API Gateway costs ($3.50/M) saving 100% of API gateway charges.
  • Python 3.12 Serverless Engine: Executes asynchronously with sub-50ms cold starts to sanitize and format incoming leads.
  • DynamoDB (On-Demand): Fast NoSQL table (uae-portfolio-leads) storing leads with zero idle maintenance costs.

4. How Code is Connected & Automatically Updated (CI/CD)

The repository on local disk (G:\Dev-main) is connected directly to AWS CodeCommit and governed by AWS CodePipeline. Whenever a commit is pushed, the entire automated lifecycle executes:

Stage 1: Source Trigger (AWS CodeCommit)
A developer pushes code to branch main. AWS CodeCommit triggers CodePipeline within 1 second.
Stage 2: Quality Gate & Validation (AWS CodeBuild)
An isolated Linux container executes buildspec.yml:
• TypeScript Validation: npx tsc --noEmit catches type conflicts, missing imports, and broken objects.
• Static Compilation: npm run build verifies that all 26 Next.js pages compile cleanly.
• If any command exits with an error code, the pipeline terminates instantly. Production is 100% untouched.
Stage 3: Automated Deployment to Staging (Amazon S3)
The validated build artifacts are extracted directly into the staging bucket (abinesh-portfolio-staging-773475891493) for automated testing.
Stage 4: Automated Staging Smoke Tests (AWS CodeBuild)
An automated synthetic health-test runner (scripts/smoke-test.sh) executes:
1. Sends HTTP GET to Staging and verifies HTTP 200 OK.
2. Dispatches a synthetic lead to the Lambda Function URL and verifies HTTP 201 Created.
• If Staging fails, the deployment halts before touching Production.
Stage 5: Production Deployment with Version Tagging (Amazon S3)
Artifacts are deployed to abinesh-portfolio-demo-773475891493. S3 Versioning assigns an immutable Version ID to every single file.
Stage 6: Global Edge Invalidation (Amazon CloudFront)
AWS CodeBuild issues a cache invalidation (/*) to CloudFront distribution EZZ3MR8AP3HUC, flushing edge nodes in Dubai, Europe, and America within seconds.

5. Protection & Instant 5-Second Rollback System

Failure Alert Dispatch

An Amazon EventBridge rule (uae-pipeline-failure-rule) monitors CodePipeline. If any stage fails:
• An SNS notification (uae-pipeline-notifications) triggers immediately.
• Email / Slack / SMS alerts are delivered with the exact failed stage and build ID.

Instant Production Rollback

Because S3 Versioning is enabled on the production bucket:
• Previous working versions of all files are preserved permanently.
• Running .\rollback.ps1 instantly invalidates bad cache and restores the previous working version in 5 seconds.
